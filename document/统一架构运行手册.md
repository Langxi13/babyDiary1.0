# 统一架构运行手册

## 当前基线

Baby Diary 只保留一套运行时和一套业务模型：

- Java 入口：`com.langxi.babydiary.BabyDiaryApplication`
- 业务 API：`/api/v3/**`
- Flyway：`backend/src/main/resources/db/migration/`
- MyBatis XML：`backend/src/main/resources/mapper/`
- 默认配置：`backend/src/main/resources/application.yml`
- 生产覆盖配置：`config/application-prod.yml`
- 公共标识：API 使用 UUID，数据库使用 `BINARY(16)`
- 媒体：`media_asset`、`media_variant` 和类型明确的关系表

旧 `/api`、`/api/v2`、公开 `/images/**`、旧 Mapper、旧实体和一次性数据迁移 CLI 均不属于源码或运行制品。生产数据库已完成统一，后续结构变化只能新增 Flyway 迁移，不修改已执行的 V1/V2。

## 分层约束

每个业务模块按 `api`、`application`、`domain`、`infrastructure` 分层：

- API 只处理 HTTP 合约、认证主体和参数校验，不依赖 infrastructure。
- application 负责用例、事务和仓储端口，不直接依赖 MyBatis Mapper。
- domain 不依赖 Spring、MyBatis 或 Servlet。
- infrastructure 实现仓储、存储、加密、客户端和运行时适配。
- 跨空间查询先校验成员关系；公共 UUID 是唯一可出现在客户端合约中的业务 ID。

`ArchitectureTest` 对上述边界执行自动检查，Spotless 对 Java 格式执行构建门禁。新增功能不得通过移动类或放宽规则绕过分层；application 新增持久化能力时先定义最小端口，再在 infrastructure 提供适配器。

## 数据与媒体不变量

- Flyway V1/V2 文件名和内容不得改写；发布前校验生产 `flyway_schema_history`。
- READY 媒体必须有 READY 的 `ORIGINAL` representation，profile 使用数据库真实值。
- 媒体签名绑定空间、资产、representation、profile、过期时间和访问上下文。
- 锁定日记正文及其媒体始终要求二次验证，列表、搜索、同步、AI 和导出不能绕过。
- Nginx 不得直接暴露 `DIARY_OBJECT_PATH`，也不得恢复 `/images/**` alias。
- 删除媒体先检查引用并进入受控生命周期；对象删除和额度释放必须幂等。

## 发布流程

资源受限服务器上只允许串行执行：

```bash
scripts/disk-audit.sh --enforce
scripts/backup.sh
scripts/verify-backup.sh backups/<timestamp>
scripts/verify.sh
scripts/verify-e2e.sh
scripts/security-scan.sh
scripts/deploy.sh
scripts/health-check.sh
```

自动测试只使用合成数据。生产验证使用只读检查和现有账户完成登录、空间、日记、相册、媒体、纪念日、草稿、AI 历史及客户端 bootstrap 冒烟，不创建公开测试数据。

## 回滚

启动、Flyway、认证、空间隔离、日记媒体或相册任一关键路径失败时停止发布：

1. 保留失败日志、Jar 和数据库现场。
2. 恢复 `deploy/backend/previous/` 与前一版前端产物。
3. 数据库若执行了新的向前迁移，优先恢复发布前已验证备份，不手工编写未经验证的反向 SQL。
4. 重新执行健康检查和只读业务冒烟。

回滚不能恢复已经删除的用户写入，因此正式部署前必须先备份并确认恢复包校验和。

## 长期维护

- 新接口只放在 `/api/v3`，不增加兼容控制器。
- 新结构只通过连续版本 Flyway 迁移演进。
- 新缓存键必须包含账户和空间作用域，并有精确失效入口。
- 新后台任务必须有幂等键、重试上限、失败状态和保留清理。
- 新媒体读取必须支持授权、Range、ETag 和受保护内容 `no-store` 语义。
- 文档、测试、压测和运维脚本必须与当前端点和当前表结构同步更新。
