# 统一架构运行手册

## 当前基线

Baby Diary 只保留一套运行时和一套业务模型：

- Java 入口：`com.langxi.babydiary.BabyDiaryApplication`
- 业务 API：`/api/v3/**`
- 产品版本：`config/release-version.properties`
- 生产数据库：`baby_diary`
- Flyway：`backend/src/main/resources/db/migration/`
- MyBatis XML：`backend/src/main/resources/mapper/`
- 默认配置：`backend/src/main/resources/application.yml`
- 生产覆盖配置：`config/application-prod.yml`
- 公共标识：API 使用 UUID，数据库使用 `BINARY(16)`
- 媒体：`media_asset`、`media_variant` 和类型明确的关系表

旧 `/api`、`/api/v2`、公开 `/images/**`、旧 Mapper、旧实体和旧字段别名均不属于源码或运行制品。`/api/v3` 作为显式协议版本保留；数据库名、环境变量、Jar、版本文件和媒体目录不再携带架构版本后缀。后续结构变化只能新增 Flyway 迁移，不修改已执行的 V1、V2、V3、V4、V5、V6。

## 分层约束

每个业务模块按 `api`、`application`、`domain`、`infrastructure` 分层：

- API 只处理 HTTP 合约、认证主体和参数校验，不依赖 infrastructure。
- application 负责用例、事务和仓储端口，不直接依赖 MyBatis Mapper。
- domain 不依赖 Spring、MyBatis 或 Servlet。
- infrastructure 实现仓储、存储、加密、客户端和运行时适配。
- 跨空间查询先校验成员关系；公共 UUID 是唯一可出现在客户端合约中的业务 ID。

`ArchitectureTest` 对上述边界执行自动检查，Spotless 对 Java 格式执行构建门禁。新增功能不得通过移动类或放宽规则绕过分层；application 新增持久化能力时先定义最小端口，再在 infrastructure 提供适配器。

## 数据与媒体不变量

- Flyway V1/V2/V3/V4/V5/V6 文件名和内容不得改写；发布前校验生产 `flyway_schema_history`。
- READY 媒体必须有 READY 的 `ORIGINAL` representation，profile 使用数据库真实值。
- 图片原始对象固定为不可变 `ORIGINAL/source`；派生版本只允许 `THUMBNAIL/compact` 和 `PREVIEW/screen`，删除或回填派生文件不得修改原图对象键、字节数或 SHA-256。
- 媒体签名绑定空间、资产、representation、profile、过期时间和访问上下文。
- 锁定日记正文、目标修订快照及被任意锁定日记引用的媒体始终要求二次验证；列表、相册、头像、分享、搜索、同步、AI 和导出不能通过其他关系绕过。
- Nginx 不得直接暴露 `DIARY_OBJECT_PATH`，也不得恢复 `/images/**` alias。
- 删除媒体先检查引用并进入受控生命周期；对象删除和额度释放必须幂等。
- 原生媒体上传使用账户/空间作用域的 UUID 幂等键；完成请求可重放，失败或删除必须释放键，现有媒体的键保持可空。
- 图片回填由单 worker、单图处理和有界批次完成；临时磁盘低于门槛时停止处理，不以并行任务换取速度。
- Redis 只缓存带账户与空间作用域的标签、日记聚合和不含存储键/校验和的相册元数据；授权结果、elevated 响应、锁定正文、签名 URL、分享和管理数据不得缓存。前端同样按账户与访问级别隔离，step-up 建立或过期时立即清空内存读缓存。
- Outbox、后台作业、提醒和 AI 定时报告必须有幂等键、有限批次、重试上限和失败状态；私密日记事件不得生成可见通知。
- 回收站日记默认30天后永久清理，增量同步默认保留90天；旧游标必须通过 `resetRequired` 明确要求客户端重建读缓存。
- `sync_change` 持久化事件发生时的可见性和所有者投影；私人日记即使已物理删除，也只能向原作者返回变更，操作者在 HTTP 响应中只使用账户 UUID。

## 发布流程

资源受限服务器上只允许串行执行：

```bash
scripts/disk-audit.sh --enforce
scripts/ensure-backup-passphrase.sh
scripts/backup.sh
scripts/verify-backup.sh backups/<timestamp>
scripts/verify.sh
scripts/verify-e2e.sh
scripts/security-scan.sh
scripts/deploy.sh
scripts/health-check.sh
scripts/requeue-media-processing.sh --report
```

格式 3 备份将数据库、对象、私有配置与 Android 签名材料全部流式加密。`/etc/baby-diary/backup-passphrase` 仅允许 root 读取，必须与异地恢复包分开保存；校验必须实际解密 SQL/gzip/tar 和签名材料，不能只检查文件存在。

自动测试只使用合成数据。生产验证使用只读检查和现有账户完成登录、空间、日记、相册、媒体、纪念日、草稿、AI 历史、客户端 bootstrap 及 Android CORS 预检冒烟，不创建公开测试数据。

历史 V3 到 V4 的结构升级以及数据库、环境和媒体目录命名收口均已完成。一次性迁移工具已从源码删除，当前运行时只有 `baby_diary`、中性环境变量和 `data/objects`；格式 3 加密备份是唯一恢复输入。

## 回滚

启动、Flyway、认证、空间隔离、日记媒体或相册任一关键路径失败时停止发布：

1. 保留失败日志、Jar 和数据库现场。
2. 恢复 `deploy/backend/previous/` 与前一版前端产物。
3. 数据库若执行了新的向前迁移，优先恢复发布前已验证备份，不手工编写未经验证的反向 SQL。
4. 重新执行健康检查和只读业务冒烟。

回滚不能恢复已经删除的用户写入，因此正式部署前必须先备份并确认恢复包校验和。

## 长期维护

- 新接口只放在 `/api/v3`，不增加兼容控制器。
- 运行配置只使用中性变量和 `baby_diary`；`V3_*` 变量只允许出现在拒绝回归测试和历史文档中。
- 新结构只通过连续版本 Flyway 迁移演进。
- 新缓存键必须包含账户和空间作用域，并有精确失效入口。
- 新后台任务必须有幂等键、重试上限、失败状态和保留清理。
- 新媒体读取必须支持授权、Range、ETag 和受保护内容 `no-store` 语义。
- 文档、测试、压测和运维脚本必须与当前端点和当前表结构同步更新。
