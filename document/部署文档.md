# 部署文档

本文档描述当前统一运行时的构建、数据库迁移、部署、验证和回滚。示例路径与域名均为占位值，真实数据库密码、JWT、邀请码、AI 密钥、站点域名和服务器地址只允许写入服务器私有文件。

## 运行结构

```text
/srv/baby-diary/
├── backend/                         # 后端源码与构建目录
├── frontend/                        # 前端源码与构建目录
├── config/application-prod.yml      # 非秘密生产配置
├── data/objects/                    # 私有统一媒体对象
├── backend/                         # 当前 Jar 与上一版 Jar（生产部署目录）
├── frontend/                        # Nginx 托管的前端产物（生产部署目录）
├── backups/                         # 权限受限的本地备份
└── scripts/
```

当前服务只运行 `com.langxi.babydiary.BabyDiaryApplication`，API 基地址为 `/api/v3`，服务端默认监听 `127.0.0.1:10002`。旧 API、旧实体/Mapper 和旧 `/images/**` 路由不进入运行制品。

生产部署由 `PROJECT_ROOT` 指定源码目录、`DEPLOY_ROOT` 指定制品目录（默认 `/srv/baby-diary`）；前端根目录保持 `0755` 供 Nginx 读取，后端 Jar 和 GC 日志目录保持 `0750`。不要把源码目录下的临时 `dist/` 或 `target/` 当作正在运行的制品目录。

## 环境要求

- Linux、systemd、Nginx
- JDK 17、Maven 3.9+、Node.js 22 LTS、npm
- MySQL 8.0+，推荐 MySQL 8.4 LTS
- Redis 7+；生产默认回环地址 `127.0.0.1:6380`
- 可选：FFmpeg/ffprobe 和支持中文的 PDF 字体

服务器约 4 CPU、3.6 GiB RAM 时，构建、迁移和 E2E 必须串行执行。不要在生产机同时运行 Maven、Gradle 和 Playwright；不要在迁移期间运行压测。

## 私有配置

生产私有环境文件为 `/etc/baby-diary/backend.env`，权限必须为 `600`，目录权限为 `700`。最小配置如下：

```bash
DB_URL='jdbc:mysql://127.0.0.1:3306/baby_diary?connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true&preserveInstants=true&useSSL=false&allowPublicKeyRetrieval=true'
DB_USERNAME=baby_diary_app
DB_PASSWORD=replace-with-private-password
SERVER_ADDRESS=127.0.0.1
DIARY_OBJECT_PATH=/srv/baby-diary/data/objects/
JWT_SECRET=replace-with-private-secret
JWT_ACCESS_EXPIRATION=900000
AUTH_REFRESH_DAYS=30
AUTH_SECURE_COOKIE=true
INVITATION_CODE_ENCRYPTION_KEY=replace-with-private-key
AI_CONFIG_ENCRYPTION_KEY=replace-with-private-key
CORS_ALLOWED_ORIGINS=https://diary.example.com
CORS_NATIVE_ORIGINS=https://localhost,capacitor://localhost
REDIS_HOST=127.0.0.1
REDIS_PORT=6380
CACHE_ENABLED=true
CACHE_PREFIX=baby-diary:cache:
OUTBOX_ENABLED=true
REMINDERS_ENABLED=true
AI_SCHEDULES_ENABLED=true
RETENTION_ENABLED=true
DIARY_TRASH_DAYS=30
SYNC_RETENTION_DAYS=90
OBJECT_STORAGE_PROVIDER=local
HEALTH_CHECK_BASE_URL=https://diary.example.com
HEALTH_CHECK_RESOLVE_HOST=diary.example.com:443:127.0.0.1
SPRINGDOC_ENABLED=false
```

启用 Web Push 时还必须同时配置 `VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY` 和有效的 `VAPID_SUBJECT`；只配置公钥不会向客户端宣告推送可用。VAPID 私钥只能存在于该私有环境文件。Redis 缓存前缀在同一 Redis 实例上必须按环境隔离，不得复用生产与测试前缀。

当前数据库为唯一的 `baby_diary`；只有没有任何账户的全新库才使用一次性 `INVITATION_CODE` 引导初始化。运行环境不得再配置 `V3_*`、`MYSQL_DATABASE`、`DIARY_FILE_PATH` 或其他已退役变量，`scripts/runtime-governance-check.sh` 会阻止带旧配置部署。

生成密钥：

```bash
openssl rand -base64 48
install -d -m 700 /etc/baby-diary
install -m 600 /dev/null /etc/baby-diary/backend.env
```

禁止把该文件、数据库 dump、媒体对象、日志或备份放入 Git。

## 构建与自动验证

先确认工作区和网络正常，再按顺序执行：

```bash
cd /srv/baby-diary
source scripts/java-env.sh
mvn "${MAVEN_SETTINGS_ARGS[@]}" -q -DskipTests clean package -f backend/pom.xml
unzip -p backend/target/Baby-Diary.jar META-INF/MANIFEST.MF | grep 'Start-Class: com.langxi.babydiary.BabyDiaryApplication'
npm --prefix frontend run test:unit
npm --prefix frontend run build
```

发布候选还应串行执行 `scripts/verify.sh`、`scripts/verify-e2e.sh` 和 `scripts/security-scan.sh`。资源受限时可先执行后端验证，再执行前端和 E2E；详细门禁见 [测试与发布验收方案](测试与发布验收方案.md)。

## 数据库备份与迁移

每次发布前先生成并验证当前统一数据库的恢复包：

```bash
scripts/backup.sh
scripts/verify-backup.sh backups/<timestamp>
```

备份脚本与运行时只读取 `DB_URL`、`DB_USERNAME` 和 `DB_PASSWORD`，MySQL 主机、端口和库名直接从 JDBC URL 解析。`MYSQL_*` 只允许作为备份命令的显式临时覆盖，不写入生产环境文件。

备份目录权限必须为 `0700`，文件权限必须为 `0600`。格式 3 恢复包将压缩数据库、LOCAL 对象归档、systemd、Nginx、私有环境和 Android 签名材料全部使用 GPG AES-256 加密；只有清单和校验和保持明文且不含秘密。加密口令文件 `/etc/baby-diary/backup-passphrase` 必须为 `0600`，与异地恢复包分开保管。源码、Git 历史、部署产物和 `.private/` 不重复进入备份。完成后应复制到服务器外的受保护介质，并在目标介质再次执行解密验证。

当前 Flyway 依次执行 V1 统一结构、V2 媒体安全与生命周期、V3 投递/保留清理、V4 统一契约/报告分页索引、V5 自适应图片派生、V6 媒体上传幂等键和 V7 读路径索引。V6 只增加可空 `client_upload_id` 与账户/空间唯一约束，V7 只增加复合读索引，不重写现有媒体或日记数据。不得修改任何已执行迁移；新增迁移需先通过 Testcontainers 空库测试、真实前一版本数据副本升级、备份恢复演练和预发布升级测试。生产启动会自动校验 Flyway checksum，校验失败时停止发布，不使用 `repair` 掩盖差异。

### 已完成的运行时收口

生产数据库、环境变量、Jar、产品版本和媒体目录的历史命名收口已经完成。源码不再提供旧数据库导入、旧环境转换或旧媒体退役工具，防止在最终运行时上重复执行一次性操作。当前恢复只接受格式 3 加密备份，结构演进只接受新的连续 Flyway 迁移；不得通过手工建旧库、恢复旧变量或复制旧脚本重新引入兼容运行时。

## systemd、Redis 与存储

`scripts/deploy.sh` 会安装 systemd runtime drop-in，覆盖服务的 Jar 和配置入口：

```ini
[Service]
ExecStart=
ExecStart=/usr/bin/java -Xms128m -Xmx768m -jar /srv/baby-diary/backend/Baby-Diary.jar --spring.config.location=file:/etc/baby-diary/application-prod.yml
```

后端使用专用 `baby-diary` 用户运行，启用 `PrivateTmp=true`，只绑定回环地址。JVM 初始堆 128 MiB、最大堆 768 MiB，systemd 软/硬内存边界为 900/1100 MiB。Redis 故障时读缓存通过熔断和单飞回源降级到数据库，缓存失效请求会在 Redis 恢复后补放；本地有界限流继续工作，但生产仍应尽快恢复 Redis，避免长期增加数据库压力。统一媒体对象目录应为独立的 `0700` 目录，对象文件为 `0600`；不要让 Nginx 直接 alias 该目录。

## Nginx

应用站点至少应包含以下路由：

```nginx
root /srv/baby-diary/frontend;
client_max_body_size 300M;
include /etc/nginx/snippets/baby-diary-security-headers.conf;

location / { try_files $uri $uri/ /index.html; }
location ^~ /api/ {
    proxy_pass http://127.0.0.1:10002/api/;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
include /etc/nginx/snippets/baby-diary-backend-health.conf;
location = /manifest.webmanifest {
    default_type application/manifest+json;
    try_files $uri =404;
}
```

不要添加旧 `/images/**` 静态 alias。V3 媒体通过带签名的 `/api/v3/public/media/**` 读取，资源策略只对该路径设置 `cross-origin`，其他同源资源保持默认策略。

## 发布与健康检查

```bash
scripts/deploy.sh
scripts/health-check.sh
```

部署顺序为 5 GiB 磁盘门禁、构建、运行治理检查、`nginx -t`、停止服务、备份上一版 Jar、替换 Jar、同步前端、启动服务、重载 Nginx、健康检查。健康检查必须通过：

- SPA 首页、日记和相册返回 `200`；
- `/api/v3/client/bootstrap` 返回 `200`；
- `https://localhost` Android 来源的 OPTIONS 预检返回 `200`，并允许认证、版本和幂等请求头；
- 未登录 `/api/v3/account/profile` 返回 `401`；
- `/actuator/health` 返回 JSON 且顶层 `status` 为 `UP`；
- `diary-backend` 和 Nginx 均为 active；
- 日志无 Flyway 失败或新增未预期 5xx。

生产冒烟只使用现有账户和只读请求；登录、相册、日记列表/详情、头像、纪念日、AI 配置读取和移动端 bootstrap 应人工确认。

媒体处理因临时磁盘不足进入最终失败状态时，先恢复至少 3 GiB 可用空间，再执行：

```bash
scripts/requeue-media-processing.sh --report
scripts/requeue-media-processing.sh --apply
```

该脚本只匹配 `MEDIA_PROCESS`、`FAILED` 和固定的临时磁盘错误文本；不得用通配 SQL 重排 AI、导出、导入或 GC 作业。执行后应确认派生版本推进且 `ORIGINAL/source` 的对象键、字节数和 SHA-256 未变化。

## 回滚与保留策略

切换后的观察窗口至少 14 天。期间保留上一版 Jar、前一版前端产物和切换前的已验证恢复包。发生启动失败、数据数量不一致、跨空间可见、媒体无法读取或连续 5xx 时：

1. 停止当前服务并保留日志、Jar 和数据库现场。
2. 恢复上一版 Jar、前端产物和对应 systemd 配置。
3. 若新 Flyway 迁移已执行且上一版不兼容，恢复发布前已验证的数据库与对象存储备份。
4. 启动上一版服务并重新执行健康检查和只读业务冒烟。

确认观察窗口结束且格式 3 加密备份已在服务器外验证后，才可删除旧 Jar 和过期恢复包。格式 1/2 明文恢复包不得继续保留。删除前再次执行隐私审查和磁盘用量确认。
