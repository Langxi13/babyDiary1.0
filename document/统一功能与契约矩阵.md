# Baby Diary 统一功能与契约矩阵

本文档是当前版本功能、API、数据模型和测试覆盖的权威索引。运行时只接受 `/api/v3` 契约；V1、V2 API、旧图片路径、旧字段别名和内部自增 ID 均不属于当前协议。业务数据以 Flyway V1-V7 建立的表为唯一来源。

## 统一契约

| 规则 | 唯一约定 |
|---|---|
| 资源标识 | HTTP 路径和响应使用 UUID `id`；自增 `bigint` 仅限仓储内部和外键 |
| 空间边界 | 空间资源必须包含 `space_id`，应用层先执行成员或写权限校验，复合外键阻止跨空间关联 |
| 列表分页 | 日记使用 `items/nextCursor/totalElements` 游标结构；`includeTotal=false` 可跳过计数；相册和 AI 报告使用服务端页码分页 |
| 媒体 | 所有媒体及嵌入媒体统一返回 `id` 和 `representations.original/thumbnail/preview/poster/waveform/transcoded`；图片列表使用 compact、全屏使用 screen、下载和导出使用 source，不存在的变体为 `null` |
| 并发更新 | 日记更新、回收站、恢复和修订恢复必须携带 `If-Match`，冲突返回 `412 DIARY_VERSION_MISMATCH` |
| 敏感内容 | 锁定日记、目标修订快照、被任意锁定日记引用的媒体及导出通过短期 `X-Step-Up-Token` 二次验证；缓存不保存 elevated 响应、授权结论或签名 URL |
| 时间 | 数据库存 UTC；账户保存 IANA 时区；客户端统一显示中文日期 |
| 错误 | 非 2xx 返回 RFC 9457 `type/title/status/detail` 及 `code/traceId/errors`，不返回堆栈和内部键 |
| 兼容策略 | 不提供旧字段回退、旧媒体 URL、旧控制器或旧归档输入；结构升级只新增 Flyway 迁移并保留现有业务数据 |

## 数据所有权

1. `account` 是身份根；密码读取和公开资料分别通过 `CredentialRepository` 与 `ProfileRepository`，公开资料模型不含密码哈希。
2. `diary_space` 是业务租户根；空间内主表和关系表必须携带 `space_id`，跨空间关系由复合外键拒绝。
3. `media_asset` 是唯一媒体根；日记、相册、收藏、头像、纪念日和 AI 提案只保存 typed relation 或资产外键，不保存文件路径字段。
4. 所有可经 HTTP 定位的实体都具有 `binary(16) public_id`；`diary_revision.public_id` 由 V4 回填并设置唯一约束。
5. 对象存储键只存在 `media_variant.storage_key`；HTTP 不返回存储提供商、对象键、内部自增 ID 或凭据密文。

## 发布门禁

每次合并必须依次通过：后端单元/集成/迁移测试、前端单元测试与生产构建、Chromium E2E、Firefox/WebKit 兼容检查、Android lint/测试/构建、隐私与运行治理脚本、备份验证、部署后健康检查和日志检查。新增或删除功能时，必须同时更新本矩阵、[API 接口文档](API接口文档.md)、[系统功能文档](系统功能文档.md)和[测试与发布验收方案](测试与发布验收方案.md)。
