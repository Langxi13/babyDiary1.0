## 固定验证入口

每次后端升级、部署脚本调整或架构治理前后，统一运行：

```bash
cd /opt/baby-diary
scripts/verify.sh
scripts/backup.sh
scripts/deploy.sh
scripts/health-check.sh
scripts/runtime-governance-check.sh
scripts/explain-key-queries.sh
```

关键约束：

- `scripts/verify.sh` 使用后端 `mvn -q clean test`，避免 Maven 增量编译复用旧 `.class`。
- `scripts/deploy.sh` 使用后端 `mvn -q -DskipTests clean package -f backend/pom.xml`。
- Maven Compiler 必须保留 `<parameters>true</parameters>`，否则 Spring 6 无法稳定解析未显式命名的 `@RequestParam`。
- Maven Surefire 必须显式预加载与 Mockito 匹配的 Byte Buddy Agent，避免受限容器或后续 JDK 禁止动态附加时测试初始化失败。
- 部署前必须执行 `scripts/backup.sh`。
- 部署后至少检查核心页面、`/actuator/health` 和未登录 `/api/v3/account/profile` 的 `401`。

## 已落地治理项

- Java 运行时和编译目标统一为 Java 17。
- Spring Boot 迁移到 3.5.16，`javax.servlet`、`javax.validation`、`javax.annotation.PostConstruct` 已迁移到 `jakarta.*`。
- Spring Security 改为 `SecurityFilterChain`、`@EnableMethodSecurity`、`requestMatchers`。
- springdoc 使用 `springdoc-openapi-starter-webmvc-ui` 2.x。
- MyBatis Spring Boot Starter 升级到 3.0.5。
- 后端使用专用系统用户 `baby-diary` 运行。
- 生产数据库连接使用业务账号 `baby_diary_app`。
- `/etc/baby-diary/backend.env` 保持 `600` 权限，敏感配置不进入仓库。
- Actuator 只暴露 `/actuator/health`。
- `RedisReadCache` 已接入账户/空间作用域读缓存，只覆盖标签、聚合统计和无存储秘密的相册元数据，并通过事务后区域版本精确失效。
- Redis 缓存异常支持30秒熔断、降级回源数据库和失效补放，不再将 Redis 短暂故障放大为业务接口失败。
- 媒体写入统一由 V3 `MediaService` 和 `ObjectStorage` 处理真实格式校验、UUID 对象键、签名 URL 和事务清理；旧版图片只由一次性迁移工具读取。
- 日记请求边界由 Jakarta Validation 与 application 跨字段校验共同约束，分页统一设置明确上限。
- 日记列表、时间轴、日历、相册详情、AI 报告历史等关键查询已补索引和 EXPLAIN 诊断脚本。
- 相册封面回退策略移除 `ORDER BY RAND()`，改为稳定选择已有图片。
- `/api/**` 已接入慢请求日志，生产默认阈值 1000ms。
- V3 使用短期访问令牌、旋转刷新会话、设备撤销、邮箱找回、恢复码和日记锁二次验证。
- 个人/共同空间、协作日记、评论回应、通知、同步、搜索、模板、洞察、提醒和空间 AI 已形成独立服务边界。
- 评论和 Emoji 回应已从日记生命周期用例中拆分为独立的 interaction 服务边界，降低 `DiaryService` 的职责密度。
- 富媒体统一经过 V3 `MediaService` 与 `ObjectStorage`，支持本地私有目录和 S3；旧版公开图片与 V3 私有对象目录强制隔离。
- ZIP v3 导入导出具备路径穿越、重复路径、版本、媒体完整性、条目数、单项大小和总解压大小保护。
- MySQL JDBC 连接强制会话使用固定东八区偏移，避免数据库生成时间受宿主机 UTC 影响，同时不依赖 MySQL 命名时区表。
- 生产 SpringDoc 默认关闭，CORS 禁止通配来源，部署治理脚本校验密钥、数据库时区和存储权限。

## 架构边界

当前代码仍保持现有包结构为主，不做大规模搬包。后续重构应按以下业务边界推进：

- `identity`：登录、注册、JWT、刷新会话、用户资料、头像、密码、恢复码和二次验证。
- `diary`、`draft`、`tag`：日记正文、修订、回收站、聚合读取、草稿、标签和心情。
- `space`：空间、成员、邀请、角色和统一访问边界。
- `sync`：离线操作幂等、增量日志、冲突和脱敏同步。
- `media`：对象存储、空间额度、签名访问、处理任务和富媒体元数据。
- `album`：系统相册、自建相册、相册组、相册照片。
- `ai`：AI 配置、模型列表、周报/月报、AI 相册推荐。
- `anniversary`、`reminder`、`notification`：纪念日、提醒、站内通知和 Web Push。
- `platform`：Problem Detail、后台作业、Outbox、保留清理、读缓存和通用运行治理。

治理原则：

- Controller 不直接访问 Mapper。
- Service 内部封装缓存失效和事务边界。
- Mapper XML 避免在索引列上使用 `YEAR()`、`MONTH()` 等函数过滤。
- 新增接口同步更新 API 文档和功能文档。
- 新增缓存必须明确 TTL、key 组成和失效入口。

## 数据库迁移基线

当前 Flyway 基线包含 `V1__clean_schema.sql`、`V2__media_security_and_lifecycle.sql`、`V3__delivery_retention_and_cleanup.sql` 和 `V4__unified_contracts_and_report_paging.sql`。旧迁移链和一次性迁移 CLI 已完成职责并删除；后续只新增连续版本迁移，不手工改业务表，也不修改任何已执行迁移。需要回滚时优先恢复部署前已验证备份，不在生产库直接执行未经验证的反向 SQL。

## 后续升级原则

- 每次升级只处理一个主变量，例如 JDK、Spring Boot、数据库驱动或前端构建工具，不和业务功能混做。
- 先补自动化测试和健康检查，再升级依赖。
- 先在本机或临时环境验证构建、启动、核心 API 冒烟，再部署生产。
- 部署后观察 `journalctl -u diary-backend`，确认没有启动异常、参数绑定异常、缓存 key 异常和慢接口异常。
- 如果登录、写日记、相册、AI 报告任一核心路径失败，立即回滚到上一提交和上一份备份。
