# 性能优化与压测指南

本文档记录 Baby Diary 当前读路径、资源边界和可重复的 staging 压测方法。压测只允许使用合成数据，禁止连接生产数据库、对象存储或 Redis。

## 验收目标

目标环境为单台 4 CPU、约 3.6 GiB RAM 的服务器，数据规模为一个空间、10,000 篇日记、20,000 个媒体资产和 10 个并发读者。重点观察 JVM 峰值、容器内存、SQL 次数、P95/P99、Redis 故障回源和导出峰值。

## 读路径约束

- 首页使用 `GET /api/v3/spaces/{spaceId}/home`，一次返回总数、4 篇日记摘要、3 个草稿标题、3 个纪念日和 6 个收藏媒体；服务端缓存 30 秒，签名 URL 在缓存读取后生成。
- 列表使用 `GET /api/v3/spaces/{spaceId}/diaries/summaries`，只返回 160 字摘要、标签、媒体总数和最多 4 张缩略图；时间轴先读取聚合索引，再按月分页读取 20 条。
- 相册目录合并为系统目录、用户目录和一次媒体批量 hydration；目录冷路径目标为 3 条业务 SQL，详情读取使用元数据、分页 ID 和批量媒体 hydration。
- elevated/step-up 读取不进入 Redis 或浏览器读缓存；普通 Redis 读取失败时通过单飞回源，避免并发请求同时压垮 MySQL。
- 导出先执行轻量 preflight，再用 keyset 批次流式写 ZIP/manifest；日记书限制 DOM 大小并以公平并发信号量保护渲染。

## 资源边界

| 组件 | 当前限制 |
| --- | --- |
| 后端 JVM | `-Xms128m -Xmx768m`，滚动 GC 日志 |
| systemd 后端 | `MemoryHigh=900M`，`MemoryMax=1100M` |
| Hikari | `minimum-idle=1`，`maximum-pool-size=8` |
| MySQL | InnoDB buffer pool 128 MiB |
| Redis | 128 MiB，`allkeys-lru`，staging 容器上限 192 MiB |
| 前端构建 | 主入口 gzip <=115 KiB，编辑器 <=130 KiB，首屏 JS <=200 KiB |

## staging 压测

准备私有环境文件：

```bash
cp config/staging.env.example .env.staging
# 替换所有 replace-with-* 值；不要提交 .env.staging
```

启动 staging、生成夹具并运行压测：

```bash
STAGING_PROJECT_NAME=baby-diary-performance scripts/start-staging.sh
STAGING_PROJECT_NAME=baby-diary-performance scripts/run-k6.sh
STAGING_PROJECT_NAME=baby-diary-performance scripts/stop-staging.sh
```

`run-k6.sh` 会创建一个合成账号和空间，写入 10,000 篇日记、20,000 个媒体资产及共享的微型对象文件，然后运行 10 个并发读者：首页、摘要、时间轴索引/月份、相册目录、相册分页和 24 张签名缩略图；同时只执行一次 EPUB 导出。默认还会停止 Redis，运行 30 秒回源场景，再自动启动 Redis。

默认门槛：

- 核心 JSON 接口：P95 < 300 ms，P99 < 800 ms。
- 签名缩略图：P95 < 250 ms，P99 < 600 ms。
- Redis 故障回源：P95 < 600 ms，HTTP 5xx 为 0，失败率 < 1%。
- 主场景检查成功率 > 99%，HTTP 5xx 为 0。

证据写入 `artifacts/k6/`：`summary.json`、`redis-outage-summary.json`、staging 日志、后端 `memory.peak`、Redis 内存信息、MySQL 状态和关键 SQL `EXPLAIN`。压测结束必须执行 `stop-staging.sh`；不要用 `docker compose down -v` 删除其他项目的卷。

## SQL 与构建门禁

后端集成测试通过请求 SQL 计数器验证：首页 <=4 条业务 SQL、日记摘要 <=4 条、相册目录 <=3 条。前端预算脚本从 Vite manifest 读取真实入口及静态依赖，避免把同名异步 `index-*` 块重复计入主包。

本地快速验证：

```bash
scripts/verify-backend.sh
scripts/verify-frontend.sh
scripts/verify-scripts.sh
git diff --check
```

本次优化未在承载其他业务容器的共享主机上执行完整 k6 实压；提交或发布前应在隔离 staging 主机保存上述证据，并将结果附在发布记录中。
